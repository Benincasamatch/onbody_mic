# Onbody Mic 路线图与验收计划

版本：文档基线 v1.0。日期：2026-10-24。软件状态：未实现。

以下是计划，不是完成记录。性能数字是待原型校准的目标，不是保证值或实测成绩。

## 1. 开发方式与交付规则

- 当前只完成需求/规划，未进入编码。
- 每阶段先确认范围，完成后提交可复现演示、测试记录、已知限制和日志，再决定下一阶段。
- 不在技术路线尚未通过可行性验证时一次性做完整项目。
- 首版以 Windows + KOOK 为纵向闭环，跨平台先通过边界与测试能力预留，不同时实现三个平台。
- 实际估时在 P0 原型之后给出；现在缺少真实硬件、KOOK 模式和 API 组合测量，不编造工期。
- 首发范围以 01 的 v1.0 基线为准：基本搜索/单级分组、两种互斥监听、预设管理与托盘已纳入后续阶段；P0/P1 不需一次实现全部，但最终交付不能未经记录删减。

## 2. 分阶段任务

### P0A：需求定稿与工程准备

前置：产品行为基线已根据 [U2] 采用，仍需用户明确授权开始开发；Q01-Q06 不再重复提问已定默认值，只采集未知的真实环境信息。

任务：

1. 读取文档基线与交接清单，确认当前阶段范围与仍未知事实，不重新猜测已定行为。
2. 记录 Windows 版本/架构、KOOK 版本与客户端形态、常用浏览器/播放器、耳机/麦克风、音效格式。
3. 确认本程序内部防误传与系统级端点独占的区别；若需要后者，提升为路线选择条件。
4. 检查已有 SDK/工具；有现成工具优先使用，缺少时先说明并获取必要安装授权。
5. 确定依赖版本与许可证登记，建立最小工程、测试工程和文档约定。

产物：需求基线、设备/软件测试清单、最小可构建工程、依赖决策记录。

门槛：核心行为不再含互相冲突的默认值；工程可以构建；不修改系统默认音频设置。

### P0B：高风险可行性验证

这一步先验证困难部分，不能把“应用隔离/低延迟”拖到界面做完之后。

任务：

1. 用选定虚拟端点播放固定测试音，确认 KOOK 可以选择并接收。
2. 将真实麦克风与一个测试 WAV 混合，验证双方同收；实际读取虚拟录音端点进行本地监听，验证与 KOOK 同时运行及监听延迟。
3. 选定浏览器/播放器进行进程树捕获；同时让另一个应用发声，检查非目标声音是否混入。
4. 验证浏览器多个标签页、应用退出/重启和无发声状态的真实捕获边界。
5. 测量初步缓冲与延迟；禁用输出设备后检查静音与恢复行为。
6. 检查第三方虚拟线被其他应用直接写入的旁路风险；确认推荐配置和路线边界。
7. 验证 KOOK 自由说话/按键说话、语音阈值、增益/降噪对短音效的影响，不自动改其配置。
8. 验证适配器激活/停止、COM 异步回调与对象生命周期，区分静音和错误；每次连接检查端点方向、身份和可写性。

产物：可丢弃的最小原型、链路图、实际支持矩阵、延迟基线、隔离证据、许可/设备说明。

门槛：所选应用与真麦/音效能够按预期送达 KOOK；实际虚拟端点可同时监听；未选应用在受控链路内不可见；问题有明确限制或用户接受的替代方案。

停止条件：需要捕获全系统声音才能“假装实现”单应用、不可接受的音效截断/延迟、无法达到确认过的隔离范围，或者设备路线不被用户接受。遇到这些问题先重新评估，不继续堆功能。

### P1：核心音频与安全路由

前置：P0B 通过。

任务：

1. 建立输入源、发送混音、监听和平台适配器的契约。
2. 实现有界缓冲、格式/声道转换、分路增益、峰值监测与基础防削波。
3. 实现统一安全闸、来源授权、会话代数和原子路由更新。
4. 实现麦克风、应用、附加音频、紧急全静音的明确语义。
5. 处理应用失效、设备变化、权限拒绝、休眠唤醒与异步释放。
6. 提供最小控制面板和脱敏指标，不先追求完整视觉效果。

产物：可独立测试的音频核心、Windows 适配器、最小操作界面、关键异常测试。

门槛：静音不可绕过、旧缓冲不补播、预览不外发；单来源失效不串源，整体故障安全关闭。

### P2：音效库与全局热键

前置：P1 安全路由稳定，音效不能另接旁路。

任务：

1. 实现导入、可解码性校验、受管素材复制、稳定 ID 和元数据。
2. 实现全局收藏/取消收藏、名称搜索、单级分组、重命名、基础排序和删除引用提示，保证元数据持久化。
3. 实现音效播放策略、立即停止、仅本地试听和短音频预加载。
4. 实现热键注册/注销、冲突提示、按住去重和单一动作分派。
5. 在目标游戏前台时测试，记录普通/提升权限、窗口/全屏等组合。
6. 测试热键连击、重复音效、损坏文件、缓存满和导入失败。

产物：可用于开黑的音效面板、热键配置页、音效库测试与使用演示。

门槛：用户能不切出游戏触发/停止指定音效；麦克风不中断；发送关闭时不会因热键自动发声。

### P3：预设、监听与日常界面

前置：核心路径和音效行为通过测试。

任务：

1. 实现预设新建、复制、重命名、删除、保存、选择、最后选择恢复和 schema 版本控制。
2. 实现应用/设备/热键失效提示，事务化预设切换与失败回滚。
3. 完成互斥的实际虚拟端点/仅音效监听、独立监听音量和仅本地试听；验证试听临时暂停自动监听且不能绕过安全停止。
4. 完成主界面、托盘、首次引导、开关状态和退出清理，不启用开机自启。
5. 保证资源缺失/配置损坏时安全关闭；实现未保存提示、原子保存与经验证的备份恢复。
6. 用户实际开黑试用，确认操作名称与开关语义不会混淆。

产物：v0.1 候选版、预设数据说明、完整操作流程、试用问题清单。

门槛：重启恢复最后预设但全部发送/监听关闭；应用任何预设后不继续旧会话、不混入旧数据；界面/热键/托盘显示同一状态，明确关窗口仍运行和退出停止的区别。

### P4：稳定性、兼容性与本地交付

前置：用户确认第一版交互可用。

任务：

1. 完整执行功能、来源边界、异常、热键和 KOOK 测试矩阵。
2. 测量空闲/负载下延迟分位数，进行连续运行与实际游戏场景验证。
3. 检查日志/崩溃处理是否暴露音频或不必要个人信息。
4. 测试干净环境的安装/运行；应用和驱动步骤分开，卸载不擅删共享驱动。
5. 输出已知限制、支持格式、支持系统、推荐配置和故障排查指南。
6. 记录发布依赖、许可证和版本；公开分发另行确认签名/捆绑/更新策略。

产物：首个可交付版本、安装包或明确的便携包、用户文档、测试报告、变更记录。

门槛：必须项通过；无法达成的项明确标注并获得用户接受；没有未处理的误传类问题。

### P5：后续扩展，不自动进入

按实际反馈选择：多应用混音、更多格式与长音频、叠加/队列策略、ducking、音效编辑、预设分享、跨平台后端或自有驱动。每项建立独立范围与可行性门槛。

| T36 | 仅音效/实际端点监听切换，夹带真麦和应用标记 | 仅音效不含真麦/应用，端点模式读真实端点；无双监听叠加或监听回送 | P1/P3 |

| T42 | 非法配置/NaN/超范围增益/未知schema/损坏备份 | 拒绝不合法数据，原文件保留，发送保持关闭；不容错扩大来源 | P3/P4 |
| T43 | full/clip监听中发起试听，期间停止/切预设/失设备 | 试听仅本地、替换原音效且暂停自动监听；安全撤销后完成回调不恢复旧监听 | P2/P3 |
| T44 | 保存失败、空间不足、素材仍被预设引用时删除 | 显示失败/依赖，不假装保存成功，不删原件/其他素材，旧配置可恢复 | P2/P3 |
| T45 | 关窗口入托盘、取消退出、实际退出 | 首次提示仍运行；取消不擅改授权；实际退出停止所有本程序音频和热键 | P3/P4 |
| T46 | extras关闭再开启，app请求/音效/preview交错 | 关闭extras撤销app并停外发clip，真麦/明确本地preview独立；重新开启不自动恢复app或旧clip | P1/P2 |

边界测试先使用数字测试音与关闭真实麦克风的条件，区分数字误混入和麦克风物理拾音。实际通话测试使用用户同意的测试环境与内容，不录制无关对话。

## 5. 低延迟与音质指标

### 5.1 指标定义

| 指标 | 测量边界 | 初步目标，待 P0 校准 |
| --- | --- | --- |
| 引擎到虚拟输入延迟 | PCM 到达本程序入口至可从虚拟录音端点采集相应样本 | ~~P95 ≤ 50 ms~~ **修订（2026-10-26，用户批准）：Steam 驱动路线 P95 ≤ 60 ms，P99 ≤ 60 ms**（实测 51-56，地板=驱动独占最小周期 20ms，10/15ms 周期被驱动降速至 0.65-0.73× 实时，证据见 devlog）；若更换支持 10ms 独占周期的驱动，恢复 50ms 目标 |
| 热键触发响应 | 本程序收到热键事件至虚拟录音端点出现预加载音效首样本 | P95 不高于 80 ms；冷缓存单独统计 |
| 本地停止响应 | 收到停止命令至虚拟录音端点停止该源的有效信号 | 目标 P95 不高于 100 ms，并记录下游缓冲尾音 |
| 源实际发声到虚拟输入 | 源测试信号时间至虚拟录音端点 | 报告实测，含捕获与设备缓冲，不偷换成内部处理耗时 |
| KOOK 端到端 | 发送端测试事件至对端实际音频输出 | 独立报告，不承诺固定值；含网络与语音处理 |

这些数字是本方案的初始工程目标，不是已证明的性能、硬件事实或对外保证。用户“按建议来”不等于接受任何实测效果；P0 需按真实环境校准，若调整门槛应记录证据与影响，不能静默降低标准后宣称达标。**2026-10-26 修订记录：引擎到虚拟输入 P95 门槛 50→60ms，依据为 200 次矩阵实测（P95 51-56ms，205/205 送达）与 Steam 驱动独占周期硬下限 20ms 的取证；用户明确批准“修订标准，用工程手段达标”，工程手段（MMCSS+自研事件泵+全缓冲写契约+10ms 捕获）已全部用尽。**

### 5.2 测量方法

1. 使用已知脉冲/短标记音和可控数字源，记录本地单调时间、缓冲深度及虚拟端点采集。
2. 使用同一时钟域或明确的同步/校准方法；不同机器不能直接相减未经同步的时间戳。
3. 每个组合至少采集 200 次事件，分别报告 P50/P95/P99、最大值、失败次数与样本数。
4. 热缓存、冷缓存、空闲、正常游戏负载分开统计；不能只挑最快一次。
5. 引擎打点不能替代外部音频测量。若回调时间戳不能反映真实端点位置，采用回环参考/采样对齐并注明误差。
6. KOOK 对端使用用户同意的测试接收端；必要时用同一记录设备或同步参考录下发送标记和接收音，报告网络条件与测量误差。
7. 分别测应用、音效、麦克风与监听路径；蓝牙设备单列，不能把设备无线缓冲归为本程序处理时间。

### 5.3 稳定性门槛建议

- 原型先连续 1 小时，候选版至少 2 小时受控测试，再做一次约 4 小时真实开黑试用。
- 内存、队列与延迟不持续单向增长；任何欠载/溢出有计数和对应时间点。
- 无需承诺绝对零掉音，但正常负载下不可出现可重复的明显爆音、长期失声或积压播放。
- CPU/内存目标在 P0 记录硬件后制定，不能在未知设备上编造百分比保证。
- 低延迟优先级不能压过安全边界：过载可受控静音/提示，但不可改捕获全系统或扩宽来源。

## 6. 支持矩阵建立规则

具体 Windows 版本仍需记录。微软样例写的是 build 20348 或更高，不能笼统宣传“所有 Windows 10 都支持应用捕获”。框架 UI 支持也不等于底层捕获能力支持。[S01][S05]

## 7. 风险登记

| 风险 | 优先级 | 应对 | 触发重新评估的条件 |
| --- | --- | --- | --- |
| 单应用捕获边界与用户直觉不一致 | 高 | 原型验证真实应用/进程树，清晰显示范围 | 必须依赖全系统捕获或无法区分用户不愿发送的来源 |
| 第三方虚拟线被其他程序写入 | 高 | 专用配置、检测/提示、明确外部边界 | 用户要求系统级独占隔离而路线无法满足 |
| KOOK 降噪/门控吞掉音效 | 高 | 真实接收端测试与推荐设置 | 可接受配置仍不能实现主要音效用途 |
| 热键在目标游戏不可用 | 高 | P2 前验证实际游戏，保留按钮/托盘备选 | 用户必需的后台控制无法可靠实现 |
| 缓冲/时钟漂移导致延迟增加 | 高 | 有界队列、指标、长时间测试 | 必须持续增加缓冲才能保持运行 |
| 预设/恢复误开麦或误换源 | 高 | 会话授权分离、关闭默认、原子切换 | 任何未处理的误传复现 |
| 监听导致重复声音/物理反馈 | 中高 | 模式区分、耳机默认、禁止内环路 | 用户必需设备组合无法接受回声 |
| 新依赖 API/打包不成熟 | 中 | 锁定验证过版本，独立适配器 | 原型资源释放、延迟或分发要求不达标 |
| “跨平台预留”变成过度设计 | 中 | 共享模型与平台边界即可，不建空插件系统 | 为未确认平台显著推迟 Windows 核心功能 |
| 驱动许可/签名限制 | 中高 | 首发应用/驱动分离，发布前复核 | 计划的分发方式不获许可 |

## 8. 完成定义

第一版不以“有窗口、能播声音”为完成标准。至少需要：

1. 用户常用场景能稳定完成：说话、捕获应用、热键音效、监听、切预设。
2. 允许的声音能送达，不允许的声音不会经本程序路径混入。
3. 关键热键在实际游戏环境中验证，存在限制时明确说明。
4. 异常时行为确定，恢复不会意外开麦/换源/补播旧声音。
5. 延迟有记录，KOOK 最终听感经过实际接收端验证。
6. 模块边界可替换，配置有版本与备份，文档和日志能交接。
7. 所有未达标项已列出且得到接受，没有隐瞒误传类缺陷。
