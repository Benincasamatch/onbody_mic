## 2. 环境登记表

每次更换机器或关键依赖后生成新的环境编号，例如 `ENV-001`。占位内容不要被程序当成真实端点 ID。

| 字段 | 当前值 | 获取方式与注意 |
| --- | --- | --- |
| 环境 ID / 采集日期 | 待采集 | 实际测试时填写 |
| Windows 版本 / build / 架构 | 待采集 | 系统实际信息；产品名字符串不能替代能力检查 |
| CPU / 内存 / 负载条件 | 待采集 | 性能目标与该环境绑定 |
| .NET SDK / runtime | 待核查 | 记录精确补丁和来源，不因规划选型就全局升级 |

| 虚拟驱动 / 版本 / 签名 | 待采集 | 按官方说明核查，不关闭安全功能强行安装 |
| 虚拟播放 / 录音端点对应关系 | 待测试 | 根据方向与实际信号确认，不只比较名称 |
| 真实麦克风 / 监听设备 | 待采集 | 设备与接口类型、采样格式；完整 ID 不放公开日志 |
| 浏览器 / 播放器 | 待采集 | 程序版本、捕获进程树、可复现测试来源 |

## 4. P0 必须完成的决策

| 编号 | 原型后需冻结的项目 | 当前状态 | 失败时处理 |
| --- | --- | --- | --- |
| G01 | 实际应用捕获范围/进程树选择 | 未验证 | 不可回退系统混音，换组合或重新评估 |
| G02 | 虚拟端点方向、共享旁路与 KOOK 同读监听 | 未验证 | 明示外部风险，不满足边界则暂停路线 |
| G03 | 初步延迟、停止尾音与源时钟策略 | 未测量 | 记录瓶颈，不能无限加缓冲或改口径 |
| G04 | WAV/MP3 解码与素材长度/大小上限 | 待实测 | 不支持项明确拒绝，不静默替代素材 |
| G05 | 缓存容量/淘汰、并发异步任务上限 | 待测量 | 所有队列有界，内存不靠无限增长撑住 |
| G06 | 增益范围、下混和削波保护 | 待验证 | 非法/过大输入被拒绝，不降低安全闸 |
| G07 | .NET/界面/音频包精确版本和可分发方式 | 待锁定 | 优先已验证方案，不擅自扩大安装范围 |
| G08 | 目标游戏热键、KOOK 门控模式 | 待实测 | 明确限制，不通过注入/绕保护补救 |

进入 P1 前至少明确 G01-G03 与 G07 的核心路线，G04-G06 必须在相关实现开始前有可检查的限制；不能将“P0 后再说”拖成最终版本仍无限制。

## 7. 阶段交付模板

每阶段完成时至少提交：

1. 本阶段范围、完成项、未完成项、范围变更与原因。
2. 构建/运行入口及所需依赖，安装/系统修改分别说明。
3. 环境编号、测试用例 ID、实际结果、证据位置。
4. 已知限制及对防误传、延迟、体验的影响。
5. 依赖/许可证变化、配置 schema 变化与迁移方法。
6. 回退和停止办法、需要用户确认的下一阶段操作。

不得把阶段性演示说成正式版本。P0 原型允许丢弃重写，但应保留验证结论与测量方法；无论是否丢弃，都不能在正常系统上留下未告知的测试驱动/安全设置。

## 9. 下一位开发者的接续顺序

1. 先读 [README](../README.md) 和 [产品需求](01-product-requirements.md)，确认 `v1.0` 指文档，不是软件。
2. 读 [注意事项](05-usage-and-precautions.md)，不能在实现中省略外部边界和安全默认。
3. 读 [架构](02-architecture-and-safety.md)、[契约](06-module-contracts-and-data.md) 与 [来源](04-sources-and-decisions.md)，按官方当前版本复核能力。
4. 确认用户已授权进入开发；检查现有环境与工具，有缺失先说明，不自动装驱动/改安全设置。
5. P0A-P4 已完成：环境、端点路线、隔离、延迟、安全路由、音效库/热键、预设/监听/日常界面（v0.1 候选 `onbody desktop`）及 P4 稳定性/交付均有证据；P4 的用户补记项见 [P4 测试报告 §5](08-p4-test-report.md)，完成后按 [P5](03-roadmap-and-acceptance.md) 规则另行确认范围。
6. 完成阶段日志与证据，再申请进入下一阶段；不从"完整计划"推断用户要求一次性完成全部项目。

这类检查只能证明文档结构和有限的一致性，不能证明 Windows/KOOK 运行时安全、性能或许可证在未来仍不变。历史开发日志保持原貌，最新状态以现行基线和新日志为准。
