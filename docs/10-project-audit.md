## 2. 已复现并修复的问题

| 问题与触发条件 | 修复与验证 |
| --- | --- |
| 自动监听关闭时直接本地试听，播放器开始但没有耳机输出 | 按需创建监听输出，停止/结束释放；回归检查耳机有样本、发送端为零 |
| 试听后立即外发新音效，交叉淡化保留了试听尾音 | 只在同模式且未停止的播放间淡化；读取锁内校验模式，试听→发送回归通过 |
| 停止/紧急静音后重开，旧淡出材料进入新播放 | 撤销路径立即 Discard 并清票据；重新播放静音素材时输出保持零 |
| 停止淡出在大块读取中结束后又恢复音量 | 读取上限约束到剩余淡出样本；尾部归零，旧音效增益独立保留 |
| 混音器持旧播放票据时读取到了替换音效 | 向播放器传入实际通过闸门校验的 epoch，过期票据拒绝 |
| 迟到的旧播放完成/设备故障回调停止新资源 | 比较 ActiveClip 与适配器实例身份；替换/故障回归通过 |
| FullEndpoint 切换为 ClipOnly 后旧 Capture 未释放 | 切模式显式释放；预览期间关闭自动监听不关闭仍需使用的试听输出 |
| 切预设保留旧应用 PID；验证器异常使状态处理不完整 | 撤销旧绑定并先发布全关状态；验证错误返回拒绝而非继续发送 |
| 泛型命令队列异常被错误转换；晚到回调在释放后抛错 | 泛型异常保持原类型，普通命令返回拒绝，释放后 Post 忽略；释放等待当前命令完成 |
| 慢解码占用命令线程及热键泵，紧急静音/停止无法及时执行 | 后台串行解码，命令线程仅校验/提交；同一模拟热键泵可及时静音，停止/切预设后旧请求不启动 |
| 电平共用历史混音最高值，静音后仍高值、麦与音效互相影响 | 每路采集最近窗口峰值，读取即复位；路由独立及静音恢复测试通过 |

新增测试集中在实际回归边界；原有持久化、素材导入/缓存、路由安全与热键测试一并运行。模拟设备测试验证的是程序内部样本与状态，不能证明真实 WASAPI、KOOK 或网络链路无故障。

## 3. 源码检查后改善的操作流程

这些改动经构建和桌面自检覆盖，未逐项做真实设备交互验收：

- 应用绑定同时保存可执行路径并提示配置已变更；切预设后明确要求绑定当前运行进程。
- 首次向导拒绝不可用端点、同一个虚拟与监听输出、缺 Capture 的完整监听；跳过向导仍显示主窗。
- 设备启用仅作用于选中的禁用端点，刷新保留未保存选择；重新枚举确认 Active。Unplugged/NotPresent 不再说成可通过启用修复。
- 发送状态不再写成“队友正在听到”；缺 Capture 配置仅影响本程序完整监听，不推断远端一定无声。
- 缺素材行不能点播放，标签可选择/双击；加载状态显示且可停止；短音效自然结束不再误报“播放未开始”。
- 重叠异步操作使用忙碌计数；窗口释放后忽略晚到 UI 更新。
- 使用正确 `NuGetAudit` 属性并启用传递依赖审计。参考 Microsoft [NuGet audit](https://learn.microsoft.com/en-us/nuget/concepts/auditing-packages) 与 [.NET 10 变更](https://learn.microsoft.com/en-us/dotnet/core/compatibility/sdk/10.0/nugetaudit-transitive-packages)。

## 4. 可复现检查与便携交付

标准 SDK 环境运行：

```powershell
dotnet restore OnbodyMic.sln --force-evaluate
dotnet build OnbodyMic.sln -c Release --no-restore
dotnet test OnbodyMic.sln -c Release --no-build --no-restore --logger trx
dotnet list OnbodyMic.sln package --vulnerable --include-transitive --no-restore --source https://api.nuget.org/v3/index.json
powershell -ExecutionPolicy Bypass -File build/build-portable.ps1
```

打包脚本现在直接寻找 SDK，不依赖被忽略的 `.tools/dev.cmd`。先在唯一暂存目录发布，再运行该发布目录内 EXE 的独立数据根自检；仅在退出码 0 且日志有 `selftest: OK` 时产出 ZIP。保留旧包，不杀用户正在使用的程序。

ZIP 内有 `win-x64/` 程序目录、快速开始、README、CHANGELOG 和 Markdown 文档。发布目录旁保留 `selftest.log`、`selftest-errors.log`、`selftest/shots/`；路径和 SHA256 由脚本输出。包自检日志是该次打包结果的直接依据。文档内开发源码/本地原始证据路径需要仓库，便携包不附源代码与 TRX。

## 5. 未完成的实机验收与已知限制

**无法确定：**本轮没有运行真实 KOOK 实收、物理快捷键、游戏前台/独占全屏、连续两小时音频和第二台干净机器验证，因此不能称“所有场景正常”。当前仅枚举到本机 Steam Render 与 AUX Capture 为 Active，这不等于端到端验证通过。

建议下一轮实机顺序：

1. 用耳机确认本地试听；远端确认试听不被收到。
2. KOOK 输入选择 AUX，分别验证讲话、音效、指定应用，再检查同时混音。
3. 加载中停止/静音、切预设、应用退出、设备拔插后检查无补播、无错误回退。
4. 验证实际快捷键与目标游戏权限/全屏组合。
5. 连续两小时运行记录欠载、异常与主观听感，再在另一台机器验证首次配置。

结构边界仍存在：共享虚拟线缆可被其他应用绕过本程序直接写入；浏览器捕获按进程树而非标签页；单条音效；大规模库、高对比度和屏幕阅读器适配未完成全面验收。底层解码 API 不支持中途取消，已开始的解码会完成后丢弃；旧任务期间新的解码等待，但静音/停止不等待解码。命令队列不面向会话回调中同步重入调用设计。

**判断：**本轮直接证据足以确认列出的回归缺陷已修复，并改善了若干误导性操作反馈；对真实设备兼容性与长期稳定性仍有信息缺口。
