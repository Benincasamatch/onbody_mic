# 随声麦使用说明与注意事项

对应软件 **0.2.0 原生音效台**。当前操作以本文为准；本轮实测与限制见 [验证记录 §10](07-validation-and-handoff.md#10-原生音效台局部-rust-迁移的本地验证)。[P4 记录](08-p4-test-report.md)和 [0.1.3 检查报告](10-project-audit.md)为历史证据，不能证明当前版本端到端通话正常。

## 1. 要求与安装

Windows x64；历史实测环境为 Windows 11、Steam Streaming Speakers、KOOK 桌面客户端。其他 Windows 版本、其他虚拟驱动、蓝牙组合未验证。单应用捕获依赖 Windows 进程回环能力。

完整解压新版便携 ZIP，进入 `win-x64` 双击 `onbodymic-desktop.exe`，保留同目录 `OnbodyMic.EngineHost.exe`；后者由桌面自动管理。便携包自带 .NET 运行时，无需预装 .NET，但需要 Microsoft Edge WebView2 Runtime。程序不安装服务或音频驱动；Steam 虚拟线缆应已存在。

升级建议退出旧版后解压到新目录。默认数据目录独立于程序目录；升级前可备份数据。预设有 schema 校验，不支持的版本会被拒绝并保持安全关闭，不做静默猜测转换。

## 2. 首次配置

1. 打开“设备设置”或“设备与预设配置”，创建预设并明确选择真实麦克风、虚拟输出 Render、监听耳机。不要将监听耳机设为同一个虚拟输出。
2. “实际虚拟麦”监听还需要线缆 Capture 端点；仅音效监听或本地试听不要求在本程序中配置 Capture。
3. 端点由你明确选择；缺失端点保留提示，不自动替换目标或改用物理扬声器。可先关闭配置面板，之后再完成配置。
4. 在 KOOK 中手动选择线缆 Capture（本机通常显示“内部 AUX 插座 (Steam Streaming Speakers)”）作为输入，避免跟随默认设备。
5. 创建/应用预设后，发送和监听全部关闭，需按需逐项开启。

设备设置支持刷新并保留尚未保存的选择。保存会重新应用预设，先关闭声音，再应用配置。端点状态含义如下：

| 状态 | 处理 |
| --- | --- |
| 可用 / Active | 可以选择使用 |
| 已禁用 / Disabled | 选中后点“启用选中端点”，程序会重新枚举确认 |
| 未插入 / Unplugged | 检查设备连接；启用操作不能代替插入硬件 |
| 未检测到 / NotPresent | 检查驱动及设备是否存在 |

不能笼统认定新机器 Capture 一定禁用。以设备枚举结果为准；历史维护包中的 CLI 可用 `OnbodyMic.Cli.exe devices --all --ids` 查看，新版便携包不附带 CLI。

## 3. 发送、试听与监听

| 目的 | 操作 |
| --- | --- |
| 发送讲话 | 开启真麦发送 |
| 发送音效 | 开启附加音频，再点音效行发送或播放热键 |
| 发送应用声音 | 绑定目标应用，开启附加音频和应用捕获 |
| 只在耳机试听 | 配置可用耳机后点本地试听，无需开启发送或自动监听 |
| 监听外发音效 | 开启监听并选“仅音效” |
| 监听虚拟端点混音 | 配置 Capture 后开启“实际虚拟麦”监听 |

本地试听会暂时接管监听，结束后恢复自动监听偏好。自动监听关闭时试听仍可工作，试听结束会释放闲置监听输出。音效同一时刻只有一条；新请求替换旧请求，同一条重触发从头播放，不循环。

加载音效时停止或全部静音会取消请求，不会加载完又突然播放。连续触发只允许最新有效请求开始；解码按单路处理，避免多个解码任务同时占用大块音频内存。

所有发送状态仅说明本程序状态，不能确认 KOOK 或远端收到。界面电平是最近采样窗口的各路峰值；诊断中的累计峰值和累计软限幅样本是历史统计，不表示此刻仍在出声。

## 4. 应用、音效库和热键

“绑定应用…”选择目标进程。配置保存可执行文件路径，运行时绑定具体进程；切预设会撤销旧进程绑定，需重新确认。应用退出/重启后如捕获失效，应重新绑定，不会回退捕获整机音频。

应用捕获包含进程树；浏览器可能包含其他标签页。建议 KOOK 桌面客户端与独立播放器分开，避免把通话声回送给队友。多个同路径进程的选择需明确目标实例。

音效库支持 WAV/MP3，单文件最大 32 MB、最长 60 秒。导入会复制到受管库，不修改原文件；重复内容可跳过或明确创建独立副本。支持搜索、收藏、单级分组、重命名、单条增益、热键、打开文件位置和删除副本。卡片“试听”和“发送”是分开的操作，更多按钮打开详情管理；缺失素材的播放按钮不可用。

“全局热键”可录制组合键、绑定、解绑并检查冲突；设置会保存。录制期间其他热键暂停分派，全部静音仍可用；后端注册使用 `MOD_NOREPEAT` 避免按住重复触发。物理按键、全屏独占、不同权限进程和具体游戏兼容性仍需实测，注册成功不能代替触发验证。

## 5. 静音、预设与退出

红色“全部静音”锁存关闭本程序发送与监听，停止音效并清除旧材料；解除后保持全关，需重新逐项开启。切预设同样先停止、清除并关闭，再应用配置。

关闭主窗口会留在托盘继续运行。要彻底停止，请使用托盘“退出”。本程序开关无法控制其他应用直接写入共享线缆的声音；“本程序发送已关闭”不保证整条虚拟线缆静音。

预设管理支持创建、复制、重命名、显式保存、恢复备份和删除。删除活动预设会撤销当前配置并保持关闭，不自动选择另一个预设。诊断页“重启音频后端”会替换后端进程，只恢复保存配置，发送、监听、音效播放和应用 PID 绑定均不自动恢复。

## 6. 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| KOOK 无声 | 检查 KOOK 输入、Capture 状态、发送开关和 KOOK 门控；程序有电平不等于远端有声 |
| 只有讲话没有音效 | 开启附加音频，检查素材和热键；关闭附加音频时播放请求拒绝，不补播 |
| 应用无声 | 重新绑定正在发声的目标进程，确认附加音频和应用捕获都已开启 |
| 本地试听无声 | 选择当前佩戴的可用耳机；检查监听音量和音效增益 |
| 完整监听无声 | 配置可用 Capture；仅音效模式仅在音效外发时有声音 |
| 回声或啸叫 | 改用耳机，降低监听增益；检查是否捕获了通话浏览器进程树 |
| 声音失真 | 降低各路增益；看当前电平和累计限幅增长；再检查 KOOK 增益/降噪 |
| 输出接入失败 | 检查已有实例、端点状态及其他程序占用，关闭旧实例后重试 |
| 静音/切预设后仍有旧声 | 若确认来自本程序，立即退出并保留日志，属于需要报告的问题 |

KOOK 自由说话、按键说话、降噪和增益都会改变最终音效表现；这些由 KOOK 控制。历史纯音被降噪滤除、延迟等结果仅适用于历史测试环境。

## 7. 数据、日志和卸载

默认数据根目录 `%LOCALAPPDATA%\OnbodyMic`，也可启动时传 `--root <目录>`：

- `settings.json`：全局设置、热键和最后预设。
- `presets/`：预设与备份。
- `library/`：受管素材副本与索引。
- `logs/onbody.log`：Rust 原生壳的本地通知日志，超过 256 KB 后轮转。
- `runtime-cache/`：自包含 .NET 后端提取的运行时文件，不是素材库。旧版 `logs/crash-*.txt` 可能仍保留，不代表新版已生成相同格式的崩溃报告。

程序没有音频上传或遥测功能。错误消息可能含环境信息，主动分享日志前请检查内容。卸载时退出后删除程序目录；仅当需要清空设置和素材时才删除数据目录。原始导入文件不受影响。

## 8. 构建、诊断与限制

源码构建与打包入口是 `build/build-desktop.ps1`，详见 [README](../README.md)。正式桌面内的诊断页显示当前状态、采样窗口峰值、累计统计、路由问题和数据目录，并提供明确重接输出与重启后端。

0.1.x 维护包的 `OnbodyMic.Desktop.exe --selftest`、`OnbodyMic.Cli.exe devices/panel/p2smoke/soak/latmatrix/monprobe` 是历史入口，不在新版便携包中。其自检只能证明旧 WinForms 布局，不能证明原生桌面或硬件有声；部分 CLI 命令会实际驱动音频。

已知边界：共享线缆旁路；应用按进程树捕获；单条音效；大规模素材库未校准；高对比度/屏幕阅读器完整可用性、Windows 10、其他驱动、蓝牙、KOOK 网页版、物理/全屏热键及当前版本两小时稳定性未完成验证。

网页/应用音频采集及导入后裁剪仍为 [P5A/P5B 待实现计划](03-roadmap-and-acceptance.md)，本版不能把网页音频采集为素材、录制草稿或裁剪入库，不显示伪装成可用功能的入口；实时应用捕获与发送不等于录制素材。

技术来源和第三方许可见 [04-sources-and-decisions.md](04-sources-and-decisions.md)。
