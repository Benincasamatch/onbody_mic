# Onbody Mic 使用说明与注意事项

版本：v0.1.0（首个可交付版本，随软件发布）  
日期：2026-10-25  
状态：本文对应已实现的 v0.1.0 便携包，描述真实可用的界面与命令；与旧版规划文档冲突之处以本文为准。本文仍明确区分"已验证"与"未验证"：所有性能与兼容性结论只来自 ENV-001 测试环境的实测记录（见 [测试报告](08-p4-test-report.md)），未测组合一律标注"未验证"。

项目需求背景见[产品需求与交互](01-product-requirements.md)，模块和信任边界见[模块架构与安全边界](02-architecture-and-safety.md)，阶段与门槛见[路线图与验收计划](03-roadmap-and-acceptance.md)，来源与许可见[04-sources-and-decisions.md](04-sources-and-decisions.md)。

## 1. 阅读约定与安全边界

- **已验证**：仅指 ENV-001（Windows 11 x64、Steam Streaming Speakers 虚拟线缆、Odo 头戴麦、Senary 耳机、KOOK 0.112.0 桌面客户端）上按 [03] 测得并记录的结论。
- **未验证**：其他 Windows 版本、其他虚拟驱动、其他硬件、其他 KOOK 版本，本文不承诺兼容。
- **不做的事**：不自动录制通话、不上传音频、不改变 KOOK 私有设置、不通过模拟按键绕过游戏或反作弊、不默认捕获全系统声音、不修改系统默认音频设备。
- 本程序的防误传控制只覆盖自身音频路径。其他应用直接写入共享虚拟线、KOOK 自行换输入、麦克风物理拾取扬声器声音，不能由本程序阻止（见 §8 已知限制）。

## 2. 系统要求与支持范围

| 项目 | 要求 / 实测 |
| --- | --- |
| 操作系统 | Windows x64。仅在 Windows 11（ENV-001 实测 build 见测试报告）验证；Windows 10 各版本未验证。单应用捕获依赖系统进程回环能力，旧 build 不保证可用 |
| 运行时 | 便携包为自包含发布，无需安装 .NET；分发目标机无需任何运行时预装 |
| 虚拟音频线缆 | 首发使用 **Steam Streaming Speakers**（Steam 自带，免安装）的隐藏 capture 端点，经 `devices`/`enable` 工具启用。不捆绑、不安装任何驱动 |
| 真实麦克风 | 有线/USB 麦克风（实测 Odo 头戴麦）；蓝牙设备未验证 |
| 监听设备 | 耳机（强推荐，见 §7 回声风险）；实测 Senary 耳机 |
| 语音软件 | KOOK 桌面客户端 0.112.0 实测通过；网页版未验证 |
| 音效格式 | WAV、MP3；单文件 ≤ 32 MB、时长 ≤ 60 秒（超限明确拒绝，不静默截断） |
| 应用捕获 | 单个应用（按进程实例绑定，按可执行路径重绑）；浏览器按进程树整应用捕获，无标签页细分 |

## 3. 安装、卸载与数据位置

### 3.1 便携包（首发形态）

1. 解压 `OnbodyMic-<版本>-portable-x64.zip` 到任意可写目录。
2. 运行 `OnbodyMic.Desktop.exe`。首次启动进入首次引导向导（见 §4）。
3. 命令行工具 `OnbodyMic.Cli.exe` 在同一目录，用于设备管理与进阶操作（§6）。

**没有安装器**：应用不写注册表、不装服务、不装驱动。卸载 = 删除解压目录 + 删除数据目录（§3.2）。这保证"应用与驱动步骤分开"（[03] T33）：卸载应用永不触碰 Steam 驱动或任何共享组件。

### 3.2 数据位置与卸载清理

- 数据根目录：`%LOCALAPPDATA%\OnbodyMic\`
  - `settings.json` — 全局设置（热键绑定、监听偏好、最后预设）
  - `presets\` — 预设文件（一预设一 JSON，含 `.bak` 备份）
  - `library\` — 受管音效库（导入时**复制**，原文件永不修改）
  - `logs\` — 运行日志与崩溃报告（见 §9）
- 卸载：删除解压目录；如需清除全部数据再删除上述数据根目录。删除库内音效只删副本，不动原始文件。

### 3.3 升级

替换解压目录中的程序文件即可；数据目录保持不变。预设 schema 有版本控制，旧版本预设按损坏处理（安全关闭、保留文件），不做静默迁移。

## 4. 首次配置

1. **启用虚拟端点**（一次性）：管理员或普通权限运行：
   - `OnbodyMic.Cli.exe devices --all --ids` 找到「内部 AUX 插座 (Steam Streaming Speakers)」的 capture 端点 ID；
   - 若状态不是 Active：`OnbodyMic.Cli.exe enable --id <端点ID>` 启用。
2. 运行 `OnbodyMic.Desktop.exe`，首次引导向导依次确认：
   - 真实麦克风（具体设备，不是"默认设备"）；
   - 虚拟输出（Steam 线缆 Render 端点）；
   - 虚拟麦 Capture（线缆 AUX 端点，供"实际虚拟麦"监听用）；
   - 监听输出（耳机；标注"（当前系统默认）"的项即系统默认）；
   - 监听偏好（默认"仅音效"）。
3. 向导创建并应用首预设。**应用预设后一切发送/监听均为关闭**，需在主窗口逐项开启。
4. 之后任何时刻：主窗口「设备设置…」按钮或托盘「设备设置...」菜单项可随时修改全部端点与监听偏好；对话框支持「刷新设备」重新扫描，保存会重新应用预设（一切先关闭，需重新开启）。
5. 在 KOOK 语音设置中把输入设备手动选为「内部 AUX 插座 (Steam Streaming Speakers)」。不依赖"默认设备"。

## 5. 主窗口与托盘

主窗口从上到下：

- **顶部应用栏**：应用名、当前预设下拉、应用预设、配置管理（新建/复制/重命名/保存/设备设置/删除）、保存、设备设置…，最右侧是红色「全部静音」。窗口变窄时会按优先级隐藏次要按钮（它们仍在「配置管理」菜单里），紧急按钮始终完整可见。
- **状态摘要**：总体状态、麦克风、附加音频、应用音频、监听、音效六枚胶囊（文字 + 颜色双通道），异常时右侧追加一行说明与处理入口。
- **音频路由**四张卡片（结构一致：标题 + 状态 + 一行说明 + 参数行）：
  - 真实麦克风：输入设备名、发送开关、输入增益；
  - 附加音频：目标应用、发送开关、捕获开关、绑定应用…、应用增益；
  - 本地监听：监听设备、模式下拉、音量滑块 + 数值（双向同步）；
  - 音效输出：当前播放内容、停止音效、音效增益。
  - 窗口较窄（< 720 DIP）时四卡自动改为单列。
- **音效库**：搜索框、只看收藏、导入音效…；列表列为 名称/时长/分组/收藏/状态（素材缺失、▶ 发送中、▶ 试听中）；下方「向队友播放 / 本地试听 / 收藏·取消 / 更多 ▾」（更多含重命名、绑定播放热键、打开文件位置、删除）。
- **全局热键**：一行摘要（超出折叠为 +N 项，悬停看全量）与「设置热键…」入口。
- **底部状态栏**：阶段、设备摘要、热键数量；右侧实时指标（峰值/削波/硬跳变/欠载，超载变红）——"队友听感炸"时先看这里区分是本程序混音过载还是 KOOK 侧处理。
- **全部静音**（红色按钮）：锁存关闭全部发送与监听并停止音效。按钮变为「解除静音（保持全关）」——解除后所有开关保持关闭，需逐项重开；播放热键、切预设、设备恢复都不能自动解除。
- **状态真实性**：所有开关与状态文字都来自 500 ms 轮询的引擎快照，不会在命令成功前显示"已开启"；命令被接受但引擎状态未变（如虚拟输出未接入）会弹「未生效」，操作失败一律显示原因与处理步骤，不会静默成功。

托盘图标菜单镜像同一状态源：发送开关、监听、全部静音、设备设置、显示主窗、退出。**关窗 ≠ 退出**：首次关窗有气球提示"仍在托盘运行"；要彻底停止（停音频线程、清缓冲、解除热键）必须用托盘"退出"。

### 5.1 热键设置

主窗口「设置热键…」打开完整编辑器：

1. 选择动作（真麦发送/附加音频/监听/停止音效/全部静音/播放指定音效/切换指定预设）；
2. 点「录制…」后按下组合键（建议带 Ctrl/Alt/Shift/Win，Esc 取消并保留原绑定）；
3. 若该组合已被其他动作占用，界面会直接指出冲突对象，不会注册；
4. 点「绑定」生效并写入 `settings.json`（重启自动恢复）；选中列表项可「清除选中绑定」。

录制期间热键分派被挂起（紧急静音除外），不会误触发正在编辑的动作。

## 6. 命令行工具（OnbodyMic.Cli.exe）

### 6.1 设备管理

```
devices [--all] [--ids]        列出端点（含被禁用项与稳定 ID）
enable --id <id> / disable --id <id>   启用/禁用端点（IPolicyConfig，不改默认设备）
sessions --id <id>             查看端点上的音频会话（判断占用/读取方）
```

### 6.2 交互面板（热键编辑入口）

`OnbodyMic.Cli.exe panel` 打开完整命令面板。桌面窗口目前**只展示**激活的热键绑定，绑定/换绑在面板完成（`hotkey bind <play|stop|extras|mute|monitor|preset> <组合键>`、`hotkey unbind`）。冲突显式拒绝；按住不重复触发；初始全部未绑定。游戏内物理按键已实测可用（自动化注入被本机安全软件拦截，见测试报告 T17 附记）。

### 6.3 诊断工具

`p2smoke`（自动冒烟）、`soak`（连续运行取证）、`latmatrix`（延迟矩阵）、`monprobe`（监听链路探针）。日常排障一般不需要。

## 7. 日常开黑流程

1. 启动程序 → 自动恢复最后预设的**配置**，全部发送/监听关闭（这是刻意设计，防误传）。
2. 检查 KOOK 输入仍选 AUX 端点。
3. 按需逐项开启：真麦发送；发音效开"附加音频"后触发播放/热键；发应用声音还需再单独开"应用发送"。
4. 需要听自己声音：选监听模式——"仅音效"只监听外发音效；"实际虚拟麦"监听线缆端点完整混音（即队友听到的一切）。两者互斥，不会叠加。
5. 结束：托盘"退出"（彻底停止）或保持托盘运行（关窗）。
6. **音效规则**：新音效替换旧音效；同一条再触发从头重播；不循环；本地试听仅本地（虚拟输出零泄漏，单测+真机双证），试听会暂停自动监听并在结束后恢复。
7. **切预设**：任何切换先停音效/试听、清缓冲、全部关闭再应用（含只改音量的预设）；之后需手动重新开启。

### 回声与"炸"声速查

| 现象 | 处置 |
| --- | --- |
| 监听有回声/啸叫 | 两种监听模式互斥由程序保证；回声几乎总是**物理拾音**（扬声器出声被麦再拾）。用耳机；监听音量调低 |
| 队友说"炸"（失真） | 看主窗指标：峰值 ≥0.99 或削计数增长 → 降低真麦/应用增益（各自独立 0–4）；指标正常仍炸 → KOOK 增益/降噪问题，调 KOOK 输入设置（本程序管不到） |
| 真麦+应用并发监听爆音 | v0.1.0 已修复（AUX mixFormat 谎报格式问题，显式 PCM16 会话）。若复现，附 `logs\onbody.log` 报告 |

## 8. 已知限制（v0.1.0 如实清单）

1. **共享线缆旁路**：Steam AUX 是共享端点，其他应用直接写入其 Render 侧的声音会绕过本程序开关进入虚拟麦。程序不能扫描或杜绝；不要让不可信应用向该端点发声。
2. **应用捕获=进程树**：浏览器会连其他标签页一起捕获。KOOK 网页版与音乐同浏览器 = 回送风险，换 KOOK 桌面客户端 + 独立播放器。
3. **热键编辑无桌面 UI**：绑定/换绑需用 `panel` CLI（桌面窗口仅展示）。桌面热键捕获控件留待后续版本。
4. **单实例**：同一可执行路径多实例绑定时按歧义拒绝（防错绑），挑选具体 pid 用面板 `bind app <pid>`。
5. **音效库上限**为工程默认（32MB/60s/缓存 60s LRU），未按大规模素材库校准。
6. **桌面壳为默认样式**：未做主题/高对比度适配；DPI 缩放已适配（P3.3）。
7. **未验证组合**：Windows 10、其他驱动路线（VB-CABLE 等）、蓝牙设备、KOOK 网页版、游戏全屏独占模式下的热键（窗口化/无边框已验证）——均未验证，不做承诺。
8. **延迟**为 ENV-001 实测值（见测试报告），非对外保证；KOOK 端到端含网络与语音处理，不在本程序控制内。
9. T17 游戏前台矩阵的完整组合（不同权限级别/独占全屏）登记为待用户补测。

## 9. 日志、崩溃报告与隐私

- **运行日志**：`%LOCALAPPDATA%\OnbodyMic\logs\onbody.log`，自动轮转（超 256KB 转存 `onbody.old.log`）。内容仅为脱敏状态与错误（无音频内容、无窗口标题、无聊天内容；音效只记库 ID 不记原文件名）。
- **崩溃报告**：程序异常时自动写入 `logs\crash-<时间戳>.txt`（类型/消息/调用栈，保留最近 5 份）。UI 线程异常会弹窗并继续运行；致命异常写入后退出。
- **不上传**：日志与崩溃报告仅存本地，程序无任何网络上传。主动导出前请自行确认内容。
- 无录音、无缓存波形转储、无遥测。

## 10. KOOK 配置建议（实测记录）

1. 输入设备手动选 AUX 端点；不跟随默认。
2. 自由说话模式下瞬态音效不受降噪影响（T27 实测定性）；平稳纯音会被降噪滤除——**不要用持续正弦类音效**。
3. 按键说话模式下音效随按键门控；需要队友始终听到音效用自由说话。
4. KOOK 的增益/降噪/门限设置在本程序之外；"本地监听正常但队友听感异常"时先调 KOOK。
5. KOOK 重启后可能回退输入设备，需人工检查（本程序只能报告自身状态）。

## 11. 故障排查总表

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| 程序启动报"输出接入失败 0x8889000A" | 是否已有一个 OnbodyMic 实例在运行（托盘/任务管理器） | 只允许一个实例；关闭旧实例再启动 |
| KOOK 完全没有声音 | KOOK 输入是否 AUX；真麦/附加音频/应用开关是否符合预期；`devices` 里 AUX 端点是否 Active | 逐项开启；端点禁用则 `enable --id`；不自动换默认设备 |
| 有讲话没音效 | 附加音频是否开启；音效是否可播放（面板 `clips`）；热键是否绑定 | 附加音频关闭时热键不排队不补播 |
| 有音效没讲话 | 麦克风连接、真麦发送开关、系统麦克风权限 | 只恢复确认过的麦克风 |
| 应用声音没进入 | 应用是否已绑定（`bind app`）；应用子开关+附加音频是否都开；应用是否在发声 | 应用重启后需重新启用绑定；不回退全系统回环 |
| 混入其他声音 | 是否把 KOOK 网页和音乐放同一浏览器；是否有其他应用写 AUX 端点（`sessions --id` 查看） | 立即关附加音频；更换组合 |
| 重启后突然有声音 | 不符合设计（启动全关） | 立即点「全部静音」并提交 `logs\onbody.log`——这是安全缺陷 |
| 切预设后有残留旧声 | 不符合设计（切换先清后应用） | 立即点「全部静音」并报告 |
| 本地有声队友听不到 | KOOK 输入端点、KOOK 门控/降噪、网络 | 本机监听正常≠远端正常；按 §10 检查 KOOK |
| 监听无声 | 设置对话框里监听输出是否=实际佩戴的耳机；"仅音效"只在外发音效时有声；"实际虚拟麦"需预设配置了 AUX Capture 端点且端点未禁用 | 按序自查；AUX 看不到则 `enable --id` |
