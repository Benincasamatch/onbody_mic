版本：文档基线 v1.0。日期：2026-10-24。软件状态：未实现。

## 1. 产品定位与名称

### 1.1 一句话定位

一个用于开黑语音的桌面音频面板：用户明确选择哪些声音可以发送，既能通过热键播放短音效，也能把浏览器或播放器声音与自己的讲话混合，送入 KOOK 等语音软件。

重点是操作快捷、低延迟、来源边界清楚，而不是制作一个完整录音棚软件。

### 1.2 工作名称

| 用途 | 建议 | 状态 |
| --- | --- | --- |
| 项目目录/仓库 | `onbody_mic` | 沿用用户暂名，不重命名目录 |
| 产品工作名 | `Onbody Mic` | 已采用为内部工作名 [U2] |
| 中文名 | 随声麦 | 已采用为内部工作名；不是商标可用性结论 |
| 描述性副标题 | 游戏语音音频面板 | 说明用途而不承诺自有驱动 |
| 代码标识 | `OnbodyMic` | 工程命名基线，尚未创建代码 |

名字没有进行商标、域名或同名软件检索。若公开发布，需另外核查。产品名与系统里的录音设备名是两件事：使用现成虚拟驱动时，KOOK 里可能显示第三方设备名，不会自然变成 `Onbody Mic`。[S02]

## 3. 产品边界

### 3.1 首发范围

| 分类 | 内容 | 基线状态 |
| --- | --- | --- |
| 用户必需 | 一个应用、一个真实麦克风、一条短音效同时可用 | 首发必做 |
| 用户必需 | 短音效导入、收藏、指定热键播放 | 首发必做；新条替换旧条，同条重播 |
| 用户必需 | 可监听实际虚拟麦克风输出 | 首发必做；另提供仅音效监听，模式互斥 |
| 用户必需 | 热键/按钮开关、多预设、恢复最后选择 | 首发必做；只恢复配置，不恢复发送 |
| 验证基线 | KOOK 实际接收、实时性测量、应用来源隔离 | 用于证明已确认目标，不是新增产品方向 |
| 安全基线 | 来源失效关闭、统一发送闸、停止音效、紧急全静音、可见状态 | 按建议采用，首发不能静默删减 |
| 基础易用性 | 分源音量、独立监听音量、名称搜索、单级分组、预设增删改/复制、托盘 | 按建议纳入首发；如需裁减须登记范围变更 |

P0/P1 可先只做最小控制界面，基础易用性在后续阶段完成。首发完整范围不等于原型必须一次做完。标签体系、高级排序、多级分类和更复杂监听路由属于后续候选。

### 3.2 建议放在后续版本的能力

- 多应用同时混音、更复杂的播放队列与音效叠加策略。
- 音效裁剪、淡入淡出、音量分析、波形编辑和录制新音效。
- 按住播放、按住说话联动、讲话自动压低背景音乐。
- 预设导入导出、音效包分享、配置迁移向导。
- 长音乐播放列表、直接解析视频文件、网络 URL 解码。
- 自研或定制品牌虚拟驱动、自动安装驱动。
- macOS/Linux 后端及对应安装器。

这些是后续候选，不进入本轮首发基线，没有排期或开发授权。将来增加需要记录范围变更。

### 3.3 明确不应暗中加入

- 自动录制通话、自动上传音频或运行数据。
- 默认捕获全系统声音或自动选择最近发声的应用。
- 绕过软件保护、游戏反作弊、操作系统权限或受保护媒体限制。
- 自动修改 KOOK、系统默认播放设备、隐私权限或安全配置。
- 浏览器标签页/网页级捕获；用户已说明无需细分应用内部。
- AI 变声、TTS、云音效商城、账号系统或机器人入会。

## 4. 典型使用流程

### 4.1 第一次设置

1. 检查系统能力与虚拟设备是否可用；缺少设备时显示官方安装指引，不私自安装。
2. 用户选择真实麦克风、虚拟播放端点和耳机/监听输出。
3. 用户在 KOOK 里明确选择对应的虚拟录音端点；不使用模糊的“跟随默认设备”。
4. 用测试音效验证“我听到什么”和“KOOK 实际收到什么”；测试不能自动加入频道发声。
5. 选择应用音源，显示应用身份和“整应用捕获”的范围说明。
6. 导入音效、设置热键、保存第一个预设。
7. 用户主动开启需要的发送路径后使用。

### 4.2 日常开黑

1. 启动后选中最后使用的预设，展示来源和设备是否仍有效。
2. 所有发送与监听保持关闭，不自动播放，不补播上次未播完的音效；恢复的是监听模式偏好，不是开启状态。
3. 用按钮或热键开启所需路径；真实麦克风与附加音频可以分别控制。
4. 游戏中按音效热键播放，用“停止音效”结束声音，不打断讲话。
5. 使用“关闭附加音频”停止音乐/音效发送，但可继续讲话。
6. 出现不确定情况时使用“紧急全静音”，关闭本程序所有发送与监听。

### 4.3 切换预设

1. 有未保存修改时先提示保存/放弃/取消；取消不改变当前会话。
2. 一旦执行“应用预设”，先关闭所有发送与监听、停止音效和试听、清空旧缓冲，再校验新配置。
3. 原子替换路由、设备引用与布局；不允许半旧半新的配置。全局热键不随预设改绑，但仍检查引用和可用性。失败则保留旧配置且维持静音，显示原因。
4. “最后使用预设”只记录成功应用的配置；用户重新按按钮/热键开启需要的路径。
5. 首发所有预设切换采用同一安全流程，即使只改音量/布局也不自动继续发送；单独调节当前音量不是预设切换。

## 5. 功能规格

### 5.1 应用音源

- 展示应用名称、必要的身份区分、当前是否可捕获、是否正在产生音频。
- 用户主动选择后才绑定，不依赖前台窗口或应用列表排序。
- 不把同名进程自动视为同一个可信应用；重启后的识别规则见架构文档。
- 首发允许一个应用源；多个应用并发留到后续，不自动把其他发声进程加入。
- 提供捕获状态、发送状态、电平、音量、独立静音。
- 应用没有发声时显示“已连接，当前无声音”，区别于“来源失效”。
- 应用退出时停止该源，其他仍有效的麦克风/音效路径按既有开关继续；不自动切成系统声音。
- 如果捕获浏览器，该浏览器其他标签页、窗口或同一进程树的声音可能进入。具体边界必须原型验证。[S01]
- 如果 KOOK 网页与音乐在同一浏览器内，队友声音可能落在所选范围，必须提示回送风险；推荐 KOOK 桌面客户端与单独音乐应用组合。

### 5.2 真实麦克风

- 建议真实麦克风作为独立音源，在本程序混音后统一送入虚拟麦克风；不是承诺 KOOK 同时选择两个输入。
- 选择具体设备，独立增益、电平与静音；不静默退回默认麦克风。
- 停止音效不关闭讲话；关闭真实麦克风不影响允许发送的音效。
- 拔掉麦克风时仅关闭麦克风源并提示，除非故障影响整个音频引擎。
- 不重复叠加未知的降噪、自动增益和回声消除。第一版优先稳定直通与基础防削波。
- 麦克风启动后关闭；用户明确开启才捕获并发送，恢复预设不自动开麦。

### 5.3 音效库

| 项目 | 第一版行为基线 |
| --- | --- |
| 导入 | 文件选择和拖放；先验证可解码性、时长、大小，再加入库 |
| 格式 | WAV、MP3 作为首批必测；FLAC/OGG 等按解码器原型结果扩展，不宣称任意文件均支持 |
| 原文件 | 复制到受管本地音效库，原文件移动后仍能播放；绝不修改原文件 |
| 身份 | 每条音效具有稳定 ID，路径/显示名称变化不破坏预设引用 |
| 管理 | 重命名、收藏/取消收藏、名称搜索、单级分组、按名称/导入时间排序、删除；高级标签/排序延期 |
| 单条控制 | 音量、播放、停止、设置/清除热键；可显示时长和当前播放状态 |
| 试听 | 仅送本地监听，明确标记“不会发送”；与“向队友播放”使用不同操作 |
| 重复导入 | 可提示重复，允许复用同一资源或创建不同配置的条目 |
| 失效文件 | 显示不可用并阻止触发，不播放其他条目作替代 |
| 删除 | 先说明哪些预设引用；只删库内副本/引用，不删用户原文件 |
| 缓存 | 常用短音效预解码；有总容量上限，不一次把全部音效塞入内存 |

第一版以短音效为中心；暂停、长文件流式播放、进度拖动、播放列表不进入首发。文件时长/大小/总缓存上限在 P0 依据实际素材和设备确定，并在导入界面告知，不能用无界内存冒充支持任意大小文件。

### 5.4 音效触发与冲突

同一时间只播放一条音效，新触发替换旧音效；同一条再次触发从头重播，不循环、不叠加、不排队。这不会打断应用背景音或真实麦克风。仅本地试听也占用同一音效播放器，避免同一音效被发送和试听重复叠加。

- 同一按键按住不应由于系统自动重复连续触发。
- 新热键冲突时明确报错，不悄悄覆盖其他动作。
- 附加音频发送关闭时，播放热键不隐式开麦、不排队等恢复后突然播放；拒绝并提示。本地试听是独立显式动作，不通过发送热键自动退回试听。
- 界面试听有单独的仅本地路径；试听结束不改变发送状态。
- 热键编辑期间暂停一般播放触发，紧急停止仍应可用。
- 模拟按键、注入游戏和绕过反作弊不进入第一版。

### 5.5 开关语义

| 操作 | 影响 | 不应影响 |
| --- | --- | --- |
| 真麦发送/静音 | 真实麦克风进入发送混音的路径；关闭时停止该源采集 | 已允许的应用/音效 |
| 应用发送开关 | 当前应用进入发送混音的路径 | 麦克风与音效 |
| 附加音频发送开关 | 应用音频与音效总闸；关闭时停止外发音效、关闭应用子开关、清相关缓冲 | 真实麦克风；已明确启动的本地试听 |
| 停止全部音效 | 当前音效播放、待播队列与相关本地试听 | 真实麦克风和应用背景音 |
| 本地监听开关 | 本程序到耳机/扬声器的监听路径 | 正在发送给 KOOK 的混音 |
| 紧急全静音 | 本程序所有发送/监听路径，停止音效，解除发送启用状态 | 系统中其他应用自身的声音；本程序无法代替系统全局静音 |
| 解除紧急静音 | 只解除锁定且仍静音；设备/配置有效才显示就绪，否则显示待配置/故障 | 不重播、不自动开麦或恢复应用声音 |

首发保留真麦发送、附加音频总开关、应用发送子开关；不增加独立音效发送总开关。应用子开关只有附加音频已开时可启用，不能隐式开启附加音频；音效播放要求附加音频已开并收到显式播放动作。总状态由实际开关汇总，不再隐藏一个用户看不到的必需总开关。安全逻辑集中，按钮与热键共享同一命令。

紧急全静音是锁存动作，不是按第二次就自动恢复；必须通过单独、明确的“解除紧急静音”操作解除，再逐路启用。启动后自然处于全部关闭状态，不能靠重启恢复活动会话。

### 5.6 本地监听

核心监听能力：从实际虚拟录音端点读取声音，仅送到用户选择的耳机。这条路径必须在 P0 验证能够与 KOOK 同时使用；它反映该端点的内容，包含被混入的真实麦克风，但仍不包含 KOOK 之后的降噪、编码、网络和对端处理。不能用它证明队友最终听感。

首发另提供“仅音效”监听：只听当前本程序外发音效、不听应用原声和自己讲话。它与“实际虚拟麦克风”监听互斥，不能同时叠加。日常默认偏好为仅音效，但监听开关启动时为关闭；用户开启后才生效。实际端点监听包含端点真实内容，即使本程序没有发送，第三方写入的声音也可能被听见。

发送前取样可以用于低延迟预监听或对照测试，但不是实际虚拟录音端点监听的替代验收；如果核心端点监听无法同时使用或延迟不可接受，必须向用户说明并讨论取舍。

监听输出设备需要明确选择并具有独立音量。切换监听模式时清旧监听缓冲，只有一个模式生效；更换监听设备时先关闭监听，再由用户开启。点击仅本地试听是明确的本地播放授权，使用同一输出设备和播放器，临时暂停自动监听，试听结束后按原监听开关恢复；若期间发生停止、紧急静音、失设备或切预设，则不得恢复。不能宣称已经替用户静音了原应用，实际端点监听可能与应用原声重叠。[S01]

监听设备失效时关闭监听，不自动切到扬声器。使用扬声器时真实麦克风可能重新拾音，软件不能保证消除这种物理反馈。

### 5.7 预设

| 保存到预设 | 不应恢复为活动状态 |
| --- | --- |
| 名称、顺序、应用来源描述 | 旧 PID、失效进程句柄 |
| 真麦/虚拟输出/监听设备的稳定标识 | 未经确认的新默认设备 |
| 各音源音量、路由配置、监听模式 | 上次正在发送或捕获的会话 |
| 音效布局、收藏/分组视图 | 上次音效进度、待播队列 |
| 固定的 replace/restart 播放策略 | 启动即自动播放、自动扩大音源范围 |

- 全局音效库被多个预设引用，不为每个预设复制一份素材。
- 收藏与分组是全局库元数据；预设只记录当前视图/布局。控制热键、音效热键和选择预设热键均是全局设置，预设不保存或重绑定它们，避免切预设后同一键意外播放另一条素材。
- 最后预设 ID 与预设内容分开保存，缺失时进入空白安全状态。
- 配置保存采用原子替换、版本号和可恢复备份；损坏时不直接输出音频。
- 预设显式保存，修改后标记“未保存”；切换/退出提示保存、放弃或取消。保存失败不假装成功，旧文件保留；紧急静音不能被保存提示阻塞。收藏等全局库元数据独立保存，失败时明确提示。
- 将来导入的预设也不能自动启用麦克风或激活热键，必须校验并确认。

### 5.8 热键动作

首发动作：指定音效播放、停止全部音效、附加音频发送开关、真麦发送/静音、紧急全静音、监听开关、选择指定预设。应用子开关首发通过界面/预设选择后显式开启；后续可扩热键。

所有组合键初始为空，不替用户占用游戏按键；由用户主动绑定。三类全局绑定分别以动作、clipId、presetId 定位目标，共同检查冲突；失效绑定明确标红，不静默替换动作。音效是否出现在当前预设布局中不改变全局绑定；只要全局库条目有效、附加闸开启且显式触发就可播放，界面必须说明这一点。删除音效/预设需清理对应绑定。当前音效重播通过再次触发同一条实现。系统注册存在冲突与保留键限制，不能承诺所有游戏都能收到同样的后台快捷键。[S08]

## 6. 界面结构建议

- 顶栏：当前预设、保存状态、虚拟输出健康状态、醒目的发送状态与紧急全静音。
- 音源区：麦克风、所选应用、音效总线三块，分别显示电平、音量、发送状态。
- 音效面板：收藏/分类/搜索，卡片显示名称、热键、播放状态；本地试听与发送播放分开。
- 监听区：耳机设备、监听模式、音量、关闭监听。
- 设置页：设备、热键、音效库位置、日志与兼容性说明。
- 托盘：状态、启用/关闭附加音频、麦克风静音、紧急全静音、打开窗口、退出。

关闭窗口默认最小化托盘，首次必须说明“仍在运行，发送不会因关窗口停止”；托盘“退出”必须停止本程序音频链路。未保存时取消退出只取消退出，不擅改之前的授权状态；紧急停止始终优先。状态不只依赖颜色，按钮文本与托盘提示应可辨识。首发不注册开机自启。

先保证在游戏过程中可操作、不会误触，再做主题和视觉装饰。不在音频可行性验证之前制作复杂界面。
