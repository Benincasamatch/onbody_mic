# Onbody Mic 模块架构与安全边界

版本：文档基线 v1.0。日期：2026-10-24。软件状态：未实现。

本文件细化 [U1][U2] 的产品基线，不是实现记录。产品开关语义以 01 为准，模块/数据细则见 06。官方能力说明以 `[Sxx]` 标识；技术选型仍是待原型验证的路线，批准文档不等于确认依赖可用或授权安装。

## 1. 架构原则

1. 先验证端到端音频路径，再制作完整界面。
2. 所有发送都经过同一个安全路由层，音效热键不能另开直通输出。
3. 捕获来源采用明确的允许列表，异常时关闭相关路径，不猜测替代来源。
4. 预设描述配置；运行会话决定是否正在发送。两者不能混为一体。
5. UI、配置、音效管理与 Windows 设备实现分离。
6. 使用已经存在且可核查的组件；只有现成接口确实不能满足要求时，才评估小型平台桥接。
7. 低延迟、稳定性和隔离都必须有测试证据，不能由“采用某库”直接推导。

## 2. 技术路线建议

| 层次 | 首选候选 | 理由与限制 |
| --- | --- | --- |
| 语言/运行时 | C# + .NET 10 LTS | 微软当前支持策略列为 LTS；实施时锁定受支持补丁，不在规划阶段安装。[S06] |
| 桌面界面 | Avalonia + MVVM | UI 有 Windows/macOS/Linux 路径；不意味着音频捕获与虚拟设备也自动跨平台。[S05] |
| Windows 音频适配 | NAudio 3.3.0 的相应模块作为评估候选 | 已核实公开正式版本和进程 loopback 声明；尚未编译或性能验证。[S04] |
| 进程捕获机制 | Windows 进程树 loopback | 官方样例最低 build 20348；粒度是进程及子进程，不是窗口/标签。仍需运行时能力检查，不能用系统 loopback 冒充。[S01] |
| 虚拟麦克风 | 预装的第三方虚拟音频端点，如基础 VB-CABLE | 首先按官方指引独立安装，应用写播放侧、KOOK 读录音侧；不能假定端点排他，分发许可需复核。[S02][S03] |
| 文件解码 | 优先使用已验证的 NAudio/系统解码能力 | 支持格式由实际测试确定；不为“任意音频”承诺万能解码 |
| 配置存储 | 版本化 JSON + 原子写入 + 备份 | 第一版规模下便于检查和迁移；日后若索引复杂再替换持久层 |
| 热键 | 平台适配接口，Windows 先评估系统热键注册 | 有冲突/保留键/游戏兼容性限制；不采用注入游戏的路径。[S08] |
| 单元测试 | .NET 测试框架 + 假音源/假输出 | 具体框架在建立工程时选择，不在规划中安装 |

NAudio 3.3.0 的发布时间较近，不能仅因是最新正式版就跳过 API、线程、释放和回归验证。是否固定该版本由原型结论决定。不要把旧版 `WasapiLoopbackCapture` 的系统混音行为误当成单应用捕获。[S04]

备选路线：若库的进程捕获封装不满足需要，在 Windows 适配器内采用官方 API 的小型 C# 互操作或 C++ 桥接。先核查现有封装、上游示例和问题，再决定是否自行补齐。桥接不等于自研虚拟音频驱动。

## 3. 为什么第一版不直接自研驱动

系统可选择的虚拟录音设备与普通应用内播放是不同层次。微软 SysVAD 是驱动样例，不是已经完成的音频线：其文档明确说明样例并不实现音频混音，捕获/loopback 使用生成音调模拟。[S09]

自研驱动还涉及签名、安装、升级、卸载、系统兼容性和故障影响。官方签名流程有证书及提交要求。[S10]

因此建议把自有驱动作为独立立项条件，而不是第一版隐藏依赖。如果第三方端点无法达到用户最终确认的隔离要求，应在原型阶段暂停并重新评估，而不是声称现成驱动天然提供独占安全边界。

## 4. 音频链路

```text
Selected application ----> AppCaptureAdapter ----> App channel -----+
Physical microphone ----> MicCaptureAdapter ----> Mic channel -----+--> Send mixer
Imported audio files ---> ClipPlayer -----------> Clip channel ----+       |
                                                                         v
                                                            Gain / peak protection
                                                                         |
                                                            Final send safety gate
                                                                         |
                                                                         v
                                                              Virtual output sink
                                                                         |
                                                              Virtual cable driver
                                                                         |
                                                            Virtual capture endpoint
                                                                         |
                                                      +------------------+-------------+
                                                      |                                |
                                                      v                                v
                                                     KOOK                  Monitor capture adapter
                                                                                       |
Clip audition ---------------------------> Local-only preview bus ---------------------+
Clip-only monitor -----------------------> Local-only monitor bus ---------------------+
                                                                                       |
                                                                                       v
                                                                             Monitor router / gain
                                                                                       |
                                                                                       v
                                                                                   Headphones
```

- 发送混音只接收已授权来源和路由。
- 核心监听从实际虚拟录音端点采集；P0 必须验证它与 KOOK 同时读取时可用。发送前取样仅作可选预监听/参考，不能替代端点监听验收。
- 本地试听/内容监听是明确标记的独立路径，不冒充端点最终内容或“队友听到的声音”。
- 仅音效与实际端点监听互斥，模式偏好可保存但开启状态不可恢复。试听占用同一音效播放器并临时暂停自动监听；由明确的本地动作授权，不可落入发送总线。
- 监听输出不再回到发送混音中，避免软件内环路。
- 推荐用户在 KOOK 手动选择虚拟录音端点，本程序读取真实麦克风。这是本项目路由建议，不是对 KOOK 自动行为的保证；其可能的切换/回退需实测。
- VB-CABLE 的 `CABLE Input` 是应用要写入的播放侧，`CABLE Output` 是 KOOK 选择的录音侧。实际枚举以设备 ID、方向与用户选择为准，不硬编码显示名称。[S02]

## 5. 模块划分与依赖方向

第一版采用一个桌面进程中的清晰模块，不默认引入微服务、后台系统服务、网络 RPC 或复杂插件市场。

| 建议项目/模块 | 职责 | 不允许承担 |
| --- | --- | --- |
| `OnbodyMic.Domain` | 预设、音效 ID、路由模型、能力模型、策略与验证规则 | Windows API、UI 控件、文件解码 |
| `OnbodyMic.Application` | 播放/停止/切预设等用例，串行控制命令，状态协调 | 直接访问 WASAPI、绕过安全层播放 |
| `OnbodyMic.Audio` | 格式规范、混音、缓冲、路由、峰值保护与测量 | 依赖窗口、扫描进程、网络上传 |
| `OnbodyMic.Media` | 音效导入、解码、缓存、素材索引 | 获取麦克风或直接连接虚拟设备 |
| `OnbodyMic.Platform.Windows` | 应用枚举、进程捕获、设备、热键、系统事件 | 保存产品业务规则或修改 KOOK 私有设置 |
| `OnbodyMic.Persistence` | JSON、迁移、素材路径、原子保存、备份 | 决定哪路声音正在发送 |
| `OnbodyMic.Desktop` | Avalonia 界面、ViewModel、托盘、组合根 | 在事件处理函数内写捕获/混音循环 |
| `OnbodyMic.Diagnostics` | 指标、脱敏日志、显式诊断导出 | 默认录音、上传窗口标题/完整路径 |

建议依赖方向：

```text
Desktop -> Application -> Domain / Audio contracts
Platform.Windows -> contracts
Media / Persistence / Diagnostics -> contracts
Composition root -> concrete implementations
```

可根据工程大小合并程序集，但不能合并职责边界。只有跨平台确实需要替换的能力才抽象，避免每个小类都造接口。

## 6. 关键接口与契约

以下是接口职责提议，不是已存在的代码或承诺的最终类名。

| 接口 | 契约 |
| --- | --- |
| `IApplicationAudioCatalog` | 列举可选择的应用实例、捕获粒度、身份和能力；不自动授权 |
| `IProcessAudioSource` | 绑定经确认的进程树，提供带时间信息的帧；失效不改绑其他应用 |
| `IMicrophoneSource` | 绑定具体输入端点，报告格式、权限与断连 |
| `IClipDecoder` | 将允许的文件转换为约定 PCM；返回受限、可取消的解码结果 |
| `IClipPlayer` | 按触发策略播放/停止，输出到指定总线，不能直接访问系统输出 |
| `IAudioOutput` | 写入明确指定端点，报告缓冲、失效和支持格式 |
| `IMonitorCapture` | 读取实际虚拟录音端点，仅允许路由至本地监听，不得回送发送混音 |
| `IRoutingPolicy` | 验证来源允许列表、路由和总闸；任何新来源先无授权 |
| `IHotkeyService` | 注册/撤销动作绑定，报告冲突，控制重复触发 |
| `IPresetStore` | 保存版本化配置、读取备份、迁移；不恢复活动发送状态 |
| `IPlatformCapabilities` | 报告支持/不支持/需权限/未验证，禁止静默降级 |

音频帧契约建议包含：格式、帧数、单调时间戳、来源 ID、会话代数、只读有效数据范围和明确的缓冲所有权。配置变化通过命令队列切换不可变快照，不在音频回调中修改共享集合。

来源健康状态与信号电平分开：API 可正常返回静音，不能只因全零样本认定捕获错误；若后端不能区分“没有流”和“有流但静音”，显示“当前未检测到声音”，不编造 `NoStream` 确认状态。[S01]

## 7. 运行状态与故障范围

### 7.1 配置、准备和发送分开

```text
Unconfigured -> ConfiguredMuted -> ReadyMuted -> Running
                                      ^             |
                                      +-- Stop -----+

Running -> SourceLost -> ReadyMuted or per-source muted
Running -> OutputLost -> FaultedMuted
Any state -> EmergencyMuted
```

- `ReadyMuted`：设备有效、配置已装载，但没有授权开始发送。
- `Running`：至少一条来源明确允许发送，不代表一定有非零声音。
- 单来源丢失：仅该来源被静音，其余已授权来源可继续。
- 虚拟输出、整体引擎或路由校验失效：整个发送混音关闭。
- 监听输出丢失：仅监听关闭，不自动切到其他扬声器。
- 应用重启/设备重新插入：重新校验身份；默认不自动恢复发送，允许用户一键重新启用。
- 紧急全静音是锁存状态，不能被播放热键、预设导入、设备恢复自动解除。
- 解除紧急静音仅回到就绪静音；若设备仍无效，则保持配置静音/故障状态，绝不伪装就绪。
- 启动、应用任何预设、休眠恢复、虚拟输出重连后，发送与监听全部关闭；单输入或单监听设备故障仅撤销相应路径。
- 仅本地试听/监听属于本地活动，不等于 `Running` 的发送状态。UI 应分别展示“正在发送”“仅本地播放/监听”和锁存状态。

### 7.2 发送判定与开关关系

```text
baseValid(source) = engineHealthy
                  AND outputVerified
                  AND sourceVerified
                  AND generationMatches
                  AND NOT emergencyMuted

maySend(mic)  = baseValid(mic)  AND micSendEnabled
maySend(app)  = baseValid(app)  AND extrasSendEnabled AND appSendEnabled
maySend(clip) = baseValid(clip) AND extrasSendEnabled AND explicitPlaybackActive
```

三个开关初始为 false。附加音频关闭同时关闭应用子开关、停止应用采集与外发音效、清相应队列；不影响真麦或已主动启动的本地试听。附加音频关闭时启用应用子开关的请求被拒绝，不暗中记录成等待生效的授权。停止全部音效同时停止外发音效与试听；它不应关闭持续实际端点监听。

`sessionArmed` 如用于内部统计，只能从显式开启状态推导，不是另一个没有 UI 的必需开关。最终闸校验会话/来源/播放代数；停止或切换后的旧回调不能因新开关状态而复活。

## 8. 防误传与信任边界

### 8.1 本程序应强制保证的规则

| ID | 规则 | 实现方向 |
| --- | --- | --- |
| B01 | 未选应用不能进入本程序发送链路 | 只开放明确进程来源，不提供系统 loopback 兜底 |
| B02 | 无法确认身份即不发送 | 名称匹配不够，校验进程身份/生命周期，歧义交给用户 |
| B03 | 热键不能绕过开关 | 热键只发送业务命令，最终安全闸统一执行 |
| B04 | 关闭后不补播旧内容 | 清空相关队列，取消音效，废弃旧会话帧 |
| B05 | 异常不自动扩大范围 | 不换默认麦克风、其他应用或其他虚拟端点 |
| B06 | 预设切换不半生效 | 确定执行后静音、清队列、校验、原子提交；失败保留旧配置但保持关闭 |
| B07 | 本地试听默认不外发 | 试听总线没有通往发送混音的边 |
| B08 | 源与开关状态可见 | 显示选中来源、发送授权、信号电平、故障原因 |

需要区别“停止提交”和“声音已经消失”：已经进入第三方驱动、KOOK 或网络缓冲的样本不能追回。测试应测量关闭后的残余尾音与实际停止时间，不能承诺瞬时删除对端已接收声音。

### 8.2 不能靠本程序保证的外部边界

1. 第三方虚拟播放端点可能同时被其他应用写入。用户若把系统默认输出或其他软件输出设成同一端点，KOOK 可能收到绕过本程序的声音。必须在原型中验证并在设置指南中明确。
2. KOOK 自己切换输入设备、自动回退或语音处理的行为，不由本程序统一控制。不能把本程序“已静音”宣传为整个电脑或 KOOK 的绝对隐私保证。
3. 所选应用内部的所有可捕获声音都在该应用范围内。浏览器标签、共享子进程、嵌入式播放器和网页通话的范围需要实测。
4. 麦克风可能拾取扬声器和环境音，这是物理输入内容，不属于数字进程白名单隔离。
5. 同一台电脑上的其他高权限软件、驱动或用户操作不在本程序的安全防护能力内。

建议配置：虚拟线不作为系统默认播放设备；普通应用继续播放到耳机；只让 Onbody Mic 写入选定虚拟线；KOOK 明确固定到对应录音端点。安装引导只检测/提示，不擅改系统配置。

若用户要求“即使其他应用主动往虚拟线写入，也绝对不能混进去”，这是比应用内部防误传更强的要求。第三方共享端点路线不能未经验证就宣称满足，需要单独验证排他机制或重新评估受控虚拟设备方案；此项是可行性阶段的停止门槛。

### 8.3 进程身份与恢复

- 预设保存可核对的应用描述，例如可执行路径或包标识；不只保存 PID。
- 实际会话同时绑定进程实例，处理 PID 复用和应用退出/重启。
- 名称相同但路径、身份或实例有歧义时不自动恢复。
- 用户选择的是应用，但 API 的实际边界是进程树。浏览器多进程架构必须实测；不能随便选一个 PID 就声称覆盖完整应用或只覆盖某个窗口。[S01]
- 不把“没有声音”当作捕获失败并偷偷换捕获方式。
- 默认不选择本程序和 KOOK 回放进程；共享浏览器内无法有效分隔时必须提示，而非假装排除了某个网页。

## 9. 音频引擎建议

### 9.1 格式与处理

- 内部优先评估 48 kHz、float32、统一声道格式；KOOK 官方排错文档也给出录制设备 48 kHz 建议，但这不是协议唯一格式要求或完整兼容保证。[S07]
- 设备不支持时显式转换格式，不静默变速或改变音调。
- 单声道麦克风与立体声音效有明确的声道映射；目标为单声道时定义下混规则并验证响度。
- 各来源增益在混音前处理，总线提供峰值监测与低延迟防削波。复杂音效和高延迟前瞻处理不进入首发。
- 实际端点监听以虚拟录音端点读到的数据为准；可与发送前参考样本对照，不应重新解码混一份声音来冒充端点输出。
- 音量默认无额外增益提升，硬上限和峰值保护策略在 P0 冻结；非法数值不进入音频回调。不把大幅提升音量当作解决 KOOK 门控的默认方案。

### 9.2 回调、线程与缓冲

- 音频回调避免文件 I/O、网络、UI 调用、无界锁和频繁分配。
- 捕获与输出之间使用有界队列，实时流过载优先维持低延迟，丢弃过时内容并计数。
- 音效优先预解码或受控分块解码，不能把文件当实时流随意丢弃以掩盖读取失败。
- 队列欠载输出静音并上报，不忙等；满/空策略在接口契约内明确。
- 每个输入和输出都有独立时钟，固定采样率转换不等于消除了长期时钟漂移。
- 使用输出时钟作为调度基准，监测队列水位与时间戳；必要时评估微量自适应重采样，不能无限扩大缓存保持表面连续。
- 监听是第二输出设备，可能有不同的时钟；监听过载不能阻塞主发送。
- UI 电平刷新降采样，不让每帧音频驱动 UI 重绘。

### 9.3 取消与原子切换

- 关闭单来源时撤销该授权、清该来源队列、递增对应 source/playback epoch，再处理异步释放；不得更新全局 epoch 导致其他有效来源中断。
- 预设切换、整体引擎故障、虚拟输出变化、紧急静音才撤销整个发送会话并更新 session epoch；监听模式/试听使用独立 monitor epoch，阻止迟到回调自动恢复监听。
- 全局停止采用高优先级控制路径，不能排在大量普通播放命令之后。
- 应用/预设切换与端点更换均先关闭相关路径，失败保持关闭；音量与热键配置事务失败则保留原有效配置，不能处于部分新配置。
- 输出恢复必须重新验证设备 ID、格式和用户授权；默认设备变化不能触发静默迁移。

## 10. 数据与存储

建议运行数据目录：`%LocalAppData%\OnbodyMic`。这里只描述未来运行位置，本次没有创建。

| 数据 | 内容 | 安全约束 |
| --- | --- | --- |
| `settings.json` | schemaVersion、最后预设 ID、界面偏好、全局动作/音效/预设选择热键 | 不保存正在发送的会话状态；切预设不改绑定 |
| `presets/` | 预设版本、来源描述、路由、增益、音效布局、监听偏好 | 不把 PID 当稳定身份，不自动启用导入配置 |
| `library/index.json` | 音效 ID、名称、单级分组、收藏、素材引用 | 收藏属全局库；删除引用要校验影响范围 |
| `library/assets/` | 用户主动导入的音频副本 | 不复制通话或麦克风录音，不修改原文件 |
| `cache/` | 可重建的解码/索引缓存 | 大小有界、可清理，删除不丢原始导入素材 |
| `logs/` | 脱敏状态、错误码和计数 | 不记录音频内容、窗口标题、命令行或不必要完整路径 |

导入文件必须限制大小、格式、解码资源与文件名；不能信任外部预设中的路径。先写临时文件、校验成功再原子替换，损坏配置回退到备份但仍保持发送关闭。

常规日志不录音。诊断包必须由用户主动导出，预览可能包含的设备/应用信息并脱敏。崩溃转储可能带入内存中的音频，不默认自动收集或上传完整转储。

## 11. 跨平台预留

| 能力 | 尽量共享 | 必须单独适配/验证 |
| --- | --- | --- |
| UI 与预设业务 | Avalonia、ViewModel、验证、音效元数据 | 托盘、窗口快捷行为 |
| 音频处理 | PCM 模型、混音、路由策略、音效触发 | 平台设备时钟/低延迟调度 |
| 文件解码 | 统一接口、测试样本 | 实际解码后端与打包许可证 |
| 应用捕获 | 选择模型、允许列表、能力提示 | 每个平台的进程/应用级捕获机制、权限 |
| 虚拟麦克风 | 输出契约 | 系统虚拟设备、安装器、权限和签名 |
| 热键 | 动作模型、冲突反馈 | 平台全局热键 API、桌面会话限制 |

不能把 Windows 的 PID、WASAPI 格式对象、设备 COM 对象放进持久化通用模型。平台不支持某项功能时显示“不支持/需权限/待验证”，不自动以全系统捕获替代。

“全平台”暂按未来 Windows/macOS/Linux 桌面适配理解，移动端和 Web 不承诺具备系统虚拟麦克风能力。若用户希望包含手机，应另开可行性范围。

## 12. 安装、发布与许可

- 第一版先做用户应用和外部驱动分离，检测缺失并提供官方指引；驱动安装需要用户明确同意。[S02]
- 不承诺零权限、无需驱动、无需重启或接收端显示自有品牌设备名。
- VB-CABLE 基础版本并非一概禁止捆绑，但有展示、捐赠模式等条件；A+B/C+D 的捆绑规则不同。发布前按场景重新核查许可。[S03]
- Avalonia 与 NAudio 的已核实许可证为 MIT，仍需保留适用声明；不代表所有传递依赖也都是 MIT。[S04][S05]
- 若将来引入 FFmpeg，需针对选定构建和分发方式单独核查，不在首版默默增加下载或许可范围。
- 普通运行不主动要求管理员；权限不足时解释并限定功能，不建议通过关闭系统安全功能或设置 `--no-sandbox` 解决本项目兼容性。
- 不自动升级用户机器上的全局 .NET、驱动或其他依赖。
