# 2026-10-26 P1.1 爆音修复（时钟漂移自适应 + 预卷 + 淡入淡出）开发日志

## 问题来源

用户 KOOK 实收复测确认人声+哔声均收到（P1 主观验证闭环），但反馈"偶尔爆音"。取证数据（KOOK 测试面板指标）：`under=1354` 欠载帧——真麦采集（Odo 引擎时钟，48k 域经 AUTOCONVERTPCM 转换）与独占渲染（Steam 线缆时钟，44.1k 域）运行在两个独立设备时钟上，实测漂移约 400ppm 量级。队列被渲染侧持续抽干 → 瞬时空读 → 插零 → 硬跳变 = 爆音；启用瞬间队列从零起步同样爆。docs/02 §9.2 预言的"固定采样率转换不等于消除长期时钟漂移，必要时评估微量自适应重采样"正是此问题。

## 修复（四项，全部落地）

1. **自适应速率消费**（`SourceChannel`）：按队列水位（目标 60ms）平滑调节消费速率，±1% 权限内线性插值重采样（控制增益 0.01、每拉取 5% 步进平滑）。慢时钟生产者 → 消费自动减速，快时钟 → 加速，队列稳定在水位。`AdaptiveRate` 选项可关（测试确定性用）。
2. **启用等待出帧**（`AudioSession.DoEnableMic/DoEnableApp`）：授权→写 ticket→启动适配器→**等到 PushedFrames 增长**（有界 150ms）→再打开发送开关。实现迭代说明：第一版等待"队列攒到 40ms"永远无法达成——泵在开关关闭期间按 T09 语义持续 drain（开关前帧不得补播），队列攒不住；改为等"捕获真正出帧"，开关翻转时的连续性由淡入兜底（实测 under=1）。
3. **欠载淡出/恢复淡入**（`SendMixer`）：部分拉取对尾部做 128 帧（~2.9ms）线性淡出，上次短缺的 feed 本次头部淡入；被 gate 拒绝的 feed 同样标记（解除静音时从零淡入）。残余抖动不可闻。
4. **硬跳变取证计数**（`SendMixer.HardSteps`）：混音输出检测相邻样本跳变 >0.5 且两侧有能量 → 计数进指标。用途：以后听到爆音时先看 `hard`——为 0 则爆音来自本程序下游（驱动/KOOK/网络），不是混音路径。

## 已知边界

- 自适应重采样为线性插值，±1% 内用于人声/应用音（P1 目标）足够；若 P4 稳定性矩阵发现音乐路径可闻劣化，再评估升 WDL 级重采样器。
- `under=1` 的单帧欠载发生在开关翻转边界，已被淡入掩盖（不可闻）；来源为预卷等待与泵周期的相位差，属可接受残余。
- KOOK 侧最终听感待用户复听确认。
